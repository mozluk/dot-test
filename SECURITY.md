# Security reporting

Report suspected vulnerabilities privately to the repository maintainers using the private vulnerability reporting channel on the repository's Security page when it is enabled. If no private channel is available, request a confidential contact without posting exploit details, credentials, personal data, or private keys in a public issue.

Use the latest maintained release and include the affected version, file locations, a minimal reproduction using disposable local data, and the impact. Never test against production accounts or public-chain funds. Supported release commitments and response timelines are determined by the maintainers; this document does not promise an SLA.
